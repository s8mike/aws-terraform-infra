# API Design

This document describes the planned API surface for `mecandjeo-mhc-monitoring`.

## Current Implemented Endpoints

### Health

- `GET /health`

Purpose:

- Used by developers, Docker health checks, load balancers, and deployment validation.

Expected response:

```json
{"status": "ok"}
```

### Root

- `GET /`

Purpose:

- Confirms the application identity and points users to `/docs`.

### Authentication

- `POST /api/auth/register`
- `POST /api/auth/login`
- `GET /api/auth/me`

Purpose:

- Register users.
- Login with email and password.
- Return a signed JWT bearer token.
- Resolve the current authenticated user from a bearer token.

Security:

- Registration hashes the password before storage.
- Login failures use a generic error.
- `/api/auth/me` requires a valid bearer token.

### Users

- `GET /api/users/`
- `GET /api/users/{user_id}`

Purpose:

- Let admins inspect user accounts.

Security:

- These endpoints require the `admin` role.
- Operators and managers are rejected with `403 Forbidden`.

### Operator Workflow

- `GET /api/operators/me/summary`
- `POST /api/shifts/start`
- `GET /api/shifts/`
- `PATCH /api/shifts/{shift_id}/end`
- `POST /api/task-logs/start`
- `PATCH /api/task-logs/{task_log_id}/end`
- `POST /api/delay-logs/start`
- `PATCH /api/delay-logs/{delay_log_id}/end`
- `POST /api/working-conditions/`

Purpose:

- Let an operator start a shift after selecting an MHC number and Shift A/B/C.
- Let an operator log task work during an active shift.
- Let an operator capture delays during an active task.
- Let an operator capture working conditions that affect performance.
- Let an operator close delays, tasks, and shifts with required end timestamps.

Security:

- Operator workflow routes require a valid JWT.
- Operator workflow routes require the `operator` role.
- Operators can only access their own shifts, tasks, delays, and summary.
- Managers are blocked from operator-only workflow routes.

### Manager Workflow

- `GET /api/manager/dashboard`
- `GET /api/manager/operators/live-status`
- `GET /api/manager/shifts/active`
- `GET /api/manager/delays/breakdown`
- `GET /api/manager/performance/trends`
- `GET /api/manager/reports`

Purpose:

- Let managers see high-level operation counts.
- Let managers monitor active operators, MHC numbers, active tasks, and active delays.
- Let managers review active shift summaries.
- Let managers analyze delay totals by category.
- Let managers compare performance by operator, crane, nature of work, or date.

Security:

- Manager workflow routes require a valid JWT.
- Manager workflow routes require the `manager` or `admin` role.
- Operator users are rejected with `403 Forbidden`.
- Manager endpoints are read-only in Phase 5.

Useful query examples:

```text
GET /api/manager/delays/breakdown?date_from=2026-08-21T00:00:00&date_to=2026-08-22T00:00:00
GET /api/manager/performance/trends?group_by=operator
GET /api/manager/performance/trends?group_by=crane
GET /api/manager/performance/trends?group_by=nature_of_work
GET /api/manager/performance/trends?group_by=date
```

### Admin Workflow

- `POST /api/admin/users`
- `PATCH /api/admin/users/{user_id}`
- `GET /api/admin/reference-data`
- `POST /api/admin/reference-data`
- `PATCH /api/admin/reference-data/{reference_data_id}`
- `GET /api/cranes/`
- `POST /api/cranes/`
- `PATCH /api/cranes/{crane_id}`

Purpose:

- Let trusted administrators manage user accounts, MHC assets, and selectable operational values.
- Preserve history by using `is_active: false` rather than delete endpoints.
- Store an audit-log entry for each administrative write.

Security:

- Every endpoint above requires an `admin` JWT role.
- Public registration creates operator accounts only.
- An admin cannot deactivate their own account or remove their own admin role.
- Duplicate user emails, crane codes/MHC numbers, and reference category/code pairs are rejected.

### Reports And Exports

- `GET /api/reports/performance`
- `GET /api/reports/performance.csv`
- `GET /api/reports/exports`

Purpose:

- Return completed-task performance with task, delay, effective-work, container, and moves-per-hour values.
- Filter results by completion date, operator, crane, or nature of work.
- Download the same task-level detail as a CSV file, including delay reasons.
- Retain export request metadata for later review.

Security:

- Report endpoints require a valid `manager` or `admin` JWT.
- Operators are rejected with `403 Forbidden`.
- Managers can see only their own export metadata; admins can see all metadata.

Example:

```text
GET /api/reports/performance?date_from=2026-09-01T00:00:00&date_to=2026-09-30T23:59:59&crane_id=7
GET /api/reports/performance.csv?nature_of_work=deck_free_bay
```

Authentication and RBAC added:

- `POST /api/auth/register`
- `POST /api/auth/login`
- `GET /api/auth/me`
- `GET /api/users/`
- `GET /api/users/{user_id}`

Security expectation:

- Protected routes must require a valid JWT.
- Role-specific routes must reject users with the wrong role.
