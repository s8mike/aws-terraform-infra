# Security And RBAC

Security is a first-class requirement for `mecandjeo-mhc-monitoring`.

## Current Security Baseline

Implemented:

- Environment-based configuration.
- No committed real secrets.
- Password storage modeled as `password_hash`.
- Password hashing with Passlib and bcrypt.
- JWT token creation and validation.
- Current-user dependency.
- Role guard dependencies.
- Register, login, and `/me` routes.
- Admin-only user inspection routes.
- Strong password validation requiring lowercase, uppercase, number, and one of `!`, `@`, `#`, `%`, `$`.
- Operator-only workflow routes.
- Manager/admin-only dashboard and analysis routes.
- Role field modeled on `users`.
- Audit log table modeled for future traceability.
- Basic security headers added in `app/main.py`.
- Public registration limited to the `operator` role.
- Admin-only account, crane, and reference-data write endpoints.
- Soft deactivation instead of hard deletion for users, cranes, and reference values.
- Audit records for Phase 6 administrative changes.
- Self-deactivation and self-demotion protection for admin accounts.
- Manager/admin-only historical reports and CSV exports.
- Export history scoped to the requesting manager, except for admin oversight.

Not implemented yet:

- Refresh tokens.
- Password reset.
- Account lockout or throttling.
- Production secret storage through AWS Secrets Manager or SSM Parameter Store.
- Bootstrap process for the first production admin account.

## Planned Roles

### operator

Allowed to:

- Start and end own shifts.
- Log own task activity.
- Log delays and working conditions.
- View own performance summary.

### manager

Allowed to:

- View active operator/MHC status.
- Review performance trends.
- Analyze delay breakdowns.
- Export reports.

### admin

Allowed to:

- Manage users.
- Manage cranes and MHC numbers.
- Manage reference data.
- Access system-level settings and audit events.

## Phase 3 Security Rules

Phase 3 verified:

- Passwords are hashed before storage.
- JWT payload includes user id and role.
- Protected routes reject missing tokens.
- Role guards reject users with insufficient permission.
- Secrets come from environment variables.
- Duplicate registration is rejected.
- Bad login credentials are rejected.
- Admin-only routes reject operator users.
- Manager users are rejected from operator-only workflow routes.
- Weak registration passwords are rejected.
- Operator users are rejected from manager-only dashboard routes.

## Beginner Note

Authentication answers: "Who are you?"

Authorization answers: "What are you allowed to do?"

RBAC means role-based access control. In this project, the user's role determines whether they can use operator, manager, or admin workflows.
