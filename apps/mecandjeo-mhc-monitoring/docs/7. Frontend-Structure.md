# Frontend Structure: What Each Folder and File Does

One short line per item. Tests sit next to the code they test and end in `.test.ts` or `.test.tsx`.
The number at the start of a test line is how many tests that file holds (107 in total).

## Top level (`frontend/`)

```
frontend/
├── index.html           Page shell that loads the app
├── package.json         Scripts and dependency list
├── package-lock.json    Exact installed versions (commit it)
├── vite.config.ts       Dev server, API proxy and test settings
├── tsconfig*.json       TypeScript settings (strict mode)
├── public/              Static files copied as they are
├── scripts/             Helper scripts for the command line
├── src/                 All application code and tests
├── node_modules/        Installed packages (generated, never edit)
└── dist/                Production build output (generated)
```

## Inside `src/`

```
src/
├── main.tsx             Starts React with the router and sign-in state
├── App.tsx              Every URL and which roles may open it
├── index.css            All styles, colors and the four themes
├── api/                 Calls to the backend and their data types
├── auth/                Sign-in state and role-based route guards
├── components/          Reusable parts of the screens
│   ├── admin/           Admin tabs and forms
│   ├── manager/         Manager tabs
│   └── operator/        Operator panels and number cards
├── constants/           Fixed choices used by forms
├── hooks/               Shared data-loading helpers
├── pages/               One file per screen
├── test/                Test setup and helpers
├── theme/               The Soft, Light, Grey and Dark themes
├── utils/               Small helpers for dates, text and validation
└── assets/              Unused template images
```

## Where to change things

```
Colors and themes                src/index.css, src/theme/themes.ts
Address of the API in dev        vite.config.ts (server.proxy)
Add or rename a screen route     src/App.tsx
Add an API call                  src/api/ (and its type in types.ts)
Password rules                   src/utils/validation.ts (match the backend)
Work types, areas, delay types   Admin screen, or app/db/seed_data.py
```
